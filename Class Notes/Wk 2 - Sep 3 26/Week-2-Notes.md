## 4. Evolution — AI progressed in waves, not a straight line

| Era | What happened |
|---|---|
| **1950** | Turing asks how we might test machine intelligence |
| **1956** | Dartmouth workshop helps establish AI as a field |
| **1950s–60s** | Perceptron + early machine-learning ideas |
| **1970s / late 1980s** | AI winters: expectations outrun capability |
| **1980s–90s** | Vision, language, and robotics become more specialized |
| **2010s** | Big data + GPUs accelerate deep learning |
| **2020s** | Generative AI and copilots enter everyday workflows |

> **Manager takeaway:** capability rises when ideas, data, and computing infrastructure finally line up.

### Origins — two ideas shaped the early conversation

| | Idea | Why it matters |
|---|---|---|
| **1** | **Dartmouth · 1956** — researchers gathered around the idea that aspects of intelligence might be described precisely enough for machines to simulate | AI became a distinct research agenda |
| **2** | **Turing · Imitation Game** — a human judge communicates through text with a person and a machine; if the judge cannot reliably tell which is which, the machine has succeeded at imitation | Behavior became testable |

## 5. The Turing test — and its limits

**Setup:** JUDGE (asks questions through text, does not know which respondent is human) → HUMAN (answers naturally from human knowledge and experience) → MACHINE (attempts to produce responses that appear human-like)

**Passing the test = convincing conversational behavior under the test conditions.**

### The important distinction

> **Human-like output is not the same as human-like understanding.**

| ✓ What the test CAN show | ! What it does NOT directly prove |
|---|---|
| Conversational imitation | Human consciousness |
| Behavioral performance | General intelligence |
| Ability to respond flexibly | Reliable factual knowledge |
| A useful benchmark for interaction | Human-like reasoning in every domain |

> **Business lesson:** evaluate the capability you need — not the impression of intelligence.

## 6. Machine learning — the key shift

> **From rules written by people → to patterns learned from examples.**

| | A · Rule-based system | B · Machine learning |
|---|---|---|
| **How it works** | Human writes the logic | Model sees many examples and adjusts internal parameters to capture useful patterns |
| **Example** | `IF invoice > $10,000 THEN route to manager` | Learn which customers are likely to churn |
| **Best when** | Rules are stable, explicit, and auditable | Patterns are too complex for simple rules |

### Two early learning ideas from the textbook

| | Example | Concept to remember |
|---|---|---|
| **1** | **Arthur Samuel · Checkers** — an early program improved its play through experience rather than relying only on a fixed list of moves | A system can improve based on examples and feedback |
| **2** | **Perceptron · Early classifier** — an early artificial-neuron model combined inputs using adjustable weights and changed those weights when it made errors | "Learning" can mean adjusting parameters |

> No equations. The business idea is simple: **examples + feedback → better classification.**

*Slides 13–14 are supporting diagrams: the perceptron (inputs → weights → weighted sum → activation function → output) and a biological-neuron / artificial-neuron comparison.*

## 8. Deep learning

> **A machine-learning approach that learns increasingly useful representations through multiple layers.**

### The three-part mental model

```
INPUT LAYER          →   HIDDEN LAYERS              →   OUTPUT LAYER
Receives raw info        Learn internal patterns        Produces the result
· Image pixels           · Edges → shapes               · Class
· Text tokens            · Words → meaning              · Prediction
· Audio features         · Signals → higher-level       · Description
· Sensor readings          features                     · Recommendation
```

> "Deep" means many learned layers — real systems can have far more than this simplified diagram.

### Why deep learning accelerated — three enablers converged

| | Enabler | Detail |
|:---:|---|---|
| **1** | **Big data** | Digital systems created huge collections of text, images, video, transactions, and sensor data |
| **2** | **GPUs + compute** | GPUs perform many numerical operations in parallel, making neural-network training dramatically faster |
| **3** | **Better architectures** | Improved designs — including **attention mechanisms** — made it easier to learn complex relationships |

*Attention and transformers are revisited later in the course.*

### What deep learning enabled

| Application | Examples |
|---|---|
| **Image recognition** | Defects · medical images · visual search |
| **Speech + language** | Voice assistants · transcription · translation |
| **Personalization** | Recommendations · ranking · next-best action |
| **Autonomous systems** | Vehicles · robots · game/virtual environments |

> Same technology family; different task, data, risk, and business value.

## 9. AI enters everyday knowledge work — Copilot

| **2** | **Refine** | Ask for a missing slide, reorganize content, or change the emphasis |

## 10. Prompt engineering — the textbook's four components

> **Goal + Context + Expectations + Source**

| Component | Question it answers | Worked example |
|---|---|---|
| **GOAL** | What do you want the AI to accomplish? | "Create a 6-slide executive briefing." |
| **CONTEXT** | Who is the audience and situation? | "Regional sales leaders reviewing Q2 performance." |
| **EXPECTATIONS** | What should the output look like? | "Concise, professional, include risks and next steps." |
| **SOURCE** | What evidence should it use? | "Use the supplied Q2 report; do not invent numbers." |

> **Prompting is business specification:** clearer inputs make the output easier to evaluate.

### Human review — a polished AI draft is still a draft

| Check | Question |
|---|---|
| **Facts** | Are names, numbers, claims, and dates correct? |
| **Source** | Did the model use the evidence you intended? |
| **Omissions** | What important context is missing? |
| **Audience** | Is the tone and level appropriate? |
| **Privacy** | Did you avoid confidential or sensitive data? |

> **UH rule of thumb:** use approved tools, protect sensitive data, and verify AI output before it influences work.

## 11. Business impact (2.7)

> **AI matters economically when it changes work, decisions, customers, or products.**

| | Pattern | Definition | Examples |
|:---:|---|---|---|
| **1** | **AUTOMATE** | Reduce repetitive effort | Document processing · routing · first-draft work |
| **2** | **AUGMENT** | Improve human judgment or capacity | Forecast support · risk review · analyst assistance |
| **3** | **PERSONALIZE** | Use data to tailor decisions at scale | Recommendations · offers · service |
| **4** | **REDESIGN** | Change the workflow itself | AI-assisted process · new roles · new products |

> The management question is not *"Do we have AI?"* It is *"What changed — and how will we measure it?"*

## Part II — From capability to business opportunity

> *Knowing that AI can do something is different from proving that an organization should use it.*

## 12. Problem first — do not start with the tool

| ✕ TOOL-FIRST — WEAK | ✓ PROBLEM-FIRST — STRONG |
|---|---|
| "Where can we use AI?" | "Which important decision or workflow is slow, costly, inconsistent, or difficult — and can we measure improvement?" |
| "Let's build a chatbot." | |
| "Can we add an agent?" | |
| **Problem:** the technology is chosen before the need is defined | **Business pain → decision/workflow → capability** |

### Strong problem statement — five pieces

| Piece | Question | Worked example |
|---|---|---|
| **PAIN** | What is not working? | Agents spend too long finding policy answers |
| **ACTOR** | Who experiences it? | Customer-service agents and customers |
| **WORKFLOW** | What decision/process? | Find the correct refund policy and respond |
| **BASELINE** | How does it perform now? | Average search time = 11 minutes |
| **KPI** | What should improve? | Target < 4 minutes; no increase in policy errors |

> **Strong version:** *"Can we reduce policy-search time from 11 to <4 minutes without increasing incorrect policy guidance?"*

### Capability fit — match the task to the simplest useful capability

| Capability | Question | Examples |
|---|---|---|
| **CLASSIFY** | What category? | spam · intent · defect |
| **PREDICT** | What is likely? | churn · demand · risk |
| **RECOMMEND** | What next/best? | product · action · offer |
| **GENERATE** | Create or transform | text · image · summary |
| **OPTIMIZE** | Best allocation? | route · schedule · price |
| **DETECT** | What is unusual? | fraud · anomaly · failure |

> ⚠️ **Sometimes the best solution is a rule, workflow redesign, search system, or better data — not AI.**

### AI suitability — five green lights before you invest

| # | Light | Test |
|:---:|---|---|
| **1** | **REPEATED / IMPORTANT** | The problem happens often enough or matters enough |
| **2** | **PATTERN / UNCERTAINTY** | There is something to learn, infer, retrieve, or generate |
| **3** | **EVIDENCE / DATA** | Credible information exists and can be accessed responsibly |
| **4** | **MEASURABLE OUTCOME** | A KPI or decision-quality measure can show improvement |
| **5** | **CONTROLLABLE RISK** | Errors can be monitored, reviewed, reversed, or bounded |

> **If one light is red, investigate the non-AI alternative before building a model.**

### Measure before building

| | Element | Detail |
|:---:|---|---|
| **1** | **BASELINE** | Current performance — e.g. 11 min average search time, 14% escalation rate |
| **2** | **KPI / TARGET** | What should improve — e.g. target < 4 min average search time |
| **3** | **GUARDRAIL** | What must not get worse — e.g. policy error rate ≤ current level |
| **4** | **ROI PREVIEW** | `(Benefit − Total cost) ÷ Total cost` — include software, integration, review, training, monitoring |

> A technically impressive prototype is not enough. **We need evidence that the organization is better off.**
